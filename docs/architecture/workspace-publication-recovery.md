# Original workspace publication recovery

This procedure family uses the existing canonical control-plane step registry,
Work Item, execution workspace and ActionIntent owners. Registration is not an
authority grant. The inactive example is archived, expired and identity-unbound;
normal reviewed Definition publication and fresh assignment admission are separate
operator actions. Shared work-continuity instructions remain applicable.

`workspace.publication.inspect.v1` reads only the exact current fenced workspace,
Work ownership, one original GitLab branch-publication intent and its receipts.
The registered operation checks the original request digest, repository, requester,
head and current assignment. Its Git observations use fixed read-only arguments
with hooks and fsmonitor disabled. It never resets Git or moves a branch/ref.

`publication.intent.recover.v1` leaves a known mismatched/dirty workspace in a
truthful waiting state for the current implementation worker to repair under its
existing authority. Changed material facts are re-read on a later explicit event
or advance; waiting is not completed recovery and does not cause model polling.
Unknown effects and historical origins use the existing original-intent read-only
reconciliation path only. Missing receipts do not prove that nothing was sent.

For a first-party, positively classified pre-push workspace-attestation refusal,
the current exact origin may reconcile the **same** intent using provider
idempotency only after the workspace matches the original requested commit and
canonical local branch, is clean, and preserves base ancestry. The original
provider rechecks full attestation, authority and remote revision CAS. The
procedure does not alter the request, original key, provider identity, history,
credential reference, or repository scope. The existing atomic retry transition
compares the observed original row under its writer lock; a concurrent unknown
outcome cannot be overwritten by a stale known-failure observation. Ordinary
ActionIntent reconciliation retains its existing authorized semantics.

An actual authenticated worker actor comes from the interpreter. A process-local
original-intent capability is active only during this registered owner invocation;
ordinary provider-action steps retain their normal generated-key checks. Repeated
running/unknown operation delivery reconciles rather than blindly repeating an
effect. No nested provider wrapper or substituted worker principal is introduced.

`publication.intent.verify.v1` succeeds only on the original exact successful
receipt and its current canonical verification for the requested head. The engine
records bounded observation Artifacts/Evidence derived from original references;
these are not fabricated provider receipts, independent QA or Work completion.
Provider delivery without required Evidence remains explicitly unverified.
