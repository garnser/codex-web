# Documentation screenshot catalog

The screenshots generated by `npm run docs:screenshots` are intentionally tied to sanitized browser fixtures.

| Capture | What reviewers should inspect |
| --- | --- |
| onboarding-control-plane | Project/workspace setup and control-plane orientation |
| providers-and-credentials | Operations provider/runtime configuration and credential-reference presentation |
| work-items-and-handoffs | Work Item state, blockers, handoffs, reconciliation and Run inspection |
| orchestration-and-actions | triggers, approvals, ActionIntent history and Evidence/verification |
| goals | Goal state and decomposition |
| decisions | Decision evidence, rationale, approval and traceability |
| executive-management | advisory Executive activation, disagreement and governed materialization |
| policy-and-authority | effective authority, exact Definition revision and simulation/impact |
| autonomy-control-center | Automation/autonomy controls, approvals, incidents, recovery, capacity, upgrades and audit |
| company-operations | governed business facts, provider health, KPI currentness and explainability |
| execution-preflight-remediation | execution profile, repository scope, typed blocker, remediation and retained retry |
| mobile-navigation | narrow-screen navigation, operator shell and touch-safe controls |
| workspace-navigation | Home/Work/Team/Automation/Operations/Organization shell and workspace switcher |
| home-overview | active Project orientation, current work, Attention and automation summary |
| agent-team-skill | Agent identity, Team membership and Skill revision/provenance |
| attention-inbox | human-action queue, severity, source links and authorized actions |
| runtime-operations | runtime enrollment, operator assurance, worker capability and Operations workflow |
| workspace-state-matrix | explicit loading, empty, degraded, error and blocked UI states |

The generated PNGs are CI artifacts rather than checked-in opaque binaries. See [the refresh contract](README.md) and [manifest](manifest.json).


The product shell uses **Home**, **Work**, **Team**, **Automation**, **Operations**, and **Organization** as the durable user-facing navigation vocabulary. Older fixture names may remain stable for reproducibility, but captions and documentation should use the current workspace terminology.
